## 4. 작업 결과 요약

### 서버 (Supabase)
- 테이블 8개, 기능 함수 27개. 테이블은 공개 키로 직접 읽을 수 없습니다(401 확인).
- 출퇴근은 하루 한 번, 휴가는 승인 시 잔여 연차 자동 계산.
- 위치 규칙(회사 반경, 300m 이내 수정)은 서버에서도 검사합니다.
- 직원 링크 재발급 시 그 직원의 기존 기기는 로그아웃됩니다. 사용 중지 직원은 접속이 막힙니다.
- 비상 로그인은 설정 화면에서 비밀번호를 정해야 쓸 수 있습니다(미설정 상태에서는 거부).

### 테스트 (T5)
- 관리자: 대시보드, 직원 관리(등록·개인 링크), 근태 기록, 신청 승인, 설정(위치 기록, 회사 위치 저장).
- 직원 휴대폰(375×812): 홈 출근·퇴근, 연차 신청, 승인 후 대시보드 반영 확인.
- 로그인 화면에 테스트용 바로가기 없음 확인.
- 콘솔 오류: 직원 화면과 로그인 화면 0건. 관리자 화면은 개발 서버의 중복 호출로 생기는 400 한 건만 있음 (배포 사이트에서는 확인하지 않음).

### 배포 (T8)
- 처음 배포 #4는 **실패**했습니다. 원인: gh-pages 안의 `mobile-web/node_modules` 마크다운을 Jekyll이 처리하다 실패.
- 조치: gh-pages 루트에 빈 `.nojekyll` 추가 (커밋 `c424dd57`). 다른 파일은 지우지 않았습니다.
- 배포 #5 성공. 실제 사이트가 서버 모드 빌드(`index-BeLmjMke.js`)로 바뀌었고, 로그인 화면에서 테스트 바로가기가 없는 것을 확인했습니다.

## 6. 팀장(오퍼스) 결정 사항

1. **gh-pages의 Flutter 사본 정리 여부.** 현재 gh-pages 브랜치에 `android/`, `release/`, `mobile-web/`, `build/` 등 Flutter 프로젝트 전체가 함께 들어 있습니다. 사이트 동작에는 영향이 없지만, 배포 빌드가 느리고 실패하기 쉬운 원인입니다. 정리할지 결정해 주세요. (정리하면 `.nojekyll`과 웹 빌드 파일만 남깁니다.)
2. **`main` 브랜치 병합 여부.** 현재 작업은 `supabase-backend`에만 있습니다. `main`에 합칠지 결정해 주세요.
3. **인수인계서(HANDOFF_HAIKU.json)의 테스트 명령 수정.** 위 5번 1항을 반영할지 결정해 주세요.
4. **배포 빌드에서 400 중복 호출 확인** (5번 2항). 필요하면 `EnterLink` 화면에서 관리자 링크 확인을 한 번만 하도록 고치는 것이 좋습니다.
