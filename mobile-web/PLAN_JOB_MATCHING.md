# 차별점 확정안 후보: 장애인 구직 등록 + 자동 연결 (대표 의견, 팀장 검토)

- 작성: Claude Haiku 5.5 (개발팀원), 2026-10-11
- 대상: Claude Opus 5.5 (팀장), 대표
- 상태: 아이디어. 구현 전 법률 검토 필요 (직업안정법, 장애인고용촉진법, 개인정보보호법, 채용절차법).

## 1. 대표님 의견
- 장애인 구직자 **등록을 같이 받고**, 조건이 맞는 구인 회사와 **자동으로 연결**하는 시스템.
- 샤플(근태)과 달리 **구직·채용 연결**이 핵심. 근태는 연결 후 관리 단계.

## 2. 흐름 (초안)
1. **구직자 등록:** 이름, 연락처, 희망 직무, 근무 지역, 근무 가능 시간, 필요한 편의(예: 휠체어 접근, 음성 안내). 장애 정보는 **본인이 원할 때만, 동의 후에만** 입력.
2. **구인 회사 등록:** 회사명, 직무, 근무 지역, 근무 시간, 제공 가능한 편의(예: 엘리베이터, 근로지원인).
3. **자동 연결 규칙:** 직무·지역·근무 시간·편의가 맞는 것끼리 목록 추천. 기존 기획(구인 등록 순서, 취업 회신 시 후순위)과 같은 규칙 사용.
4. **연락:** 시스템은 **연결 소개까지**. 면접·계약은 회사와 구직자가 직접 진행 (중개 범위는 법률 확인 후 결정).
5. **결과 기록:** 연결 후 취업 여부를 회신받아 기록 (성과 통계는 개인 식별 없이).

## 3. 법률 확인이 필요한 것 (반드시 먼저)
- **직업안정법:** 구직자와 구인자를 **유료로** 연결하면 직업소개사업 등록 대상일 수 있음. **무료로 할지, 유료로 할지** 먼저 결정 필요. 무료 소개도 신고 여부 확인.
- **장애 정보는 민감정보:** 개인정보보호법상 별도 동의와 최소 수집 필요. 채용에 쓰는 목적 외 사용 금지.
- **채용절차법:** 구직자에게 받을 수 있는 정보의 범위(채용과 관계없는 정보 수집 금지). 장애 정보를 구인 회사에 보일 때 **본인 동의**가 필요.
- **장애인고용촉진법:** 구인 회사가 장애인을 채용할 때 받을 수 있는 지원, 장애인 채용 시 편의 제공 의무와 연결되는 부분 확인.
- 위 항목은 **노무사나 변호사 확인**이 필요합니다. 이 문서는 법률 자문이 아닙니다.

## 4. 구현 방식 (법률 확인 후)
- 구직자 정보와 구인 정보는 **별도 테이블**, 연결 기록도 별도.
- 장애 정보 칸은 **별도 동의 기록**(동의 시각, 동의 범위)과 함께 저장. 동의를 철회하면 즉시 보이지 않게.
- 관리자 화면에서 구직자 이름·연락처는 기본적으로 **가림 처리**(별표), 필요할 때만 열람 기록 남김.
- 주민등록번호는 수집하지 않음.

## 5. 우선 순서 (제안)
1. 법률 검토 (무료/유료, 신고 여부, 동의 문구)
2. 구직자 등록 폼 (장애 정보는 선택, 동의 후에만)
3. 구인 회사 등록과 수동 추천 (관리자가 보고 연결)
4. 자동 추천 규칙 적용
5. 연결 결과 기록과 통계

## 6. 팀장 결정 요청
- 무료 소개로 할지, 유료로 할지
- 법률 검토 담당(노무사 등) 지정
- 앱 전환과 함께 할지, 지금 웹에서 먼저 할지
## 수익 구조 메모 (대표 질문: 구직은 무료, 앱 사용료는 받는다)
- 구직자: **무료** (장애인 구직자 부담 없음, 권장).
- 구인 회사: **앱 사용료(월 구독)** 를 받는 구조로 검토.
- 주의 1: 사용료가 **취업 성사 건수나 연봉에 따라 달라지면** 직업소개(알선) 수수료로 볼 수 있음 → 직업안정법상 유료직업소개 등록 대상 위험. **성과 연동 금지.**
- 주의 2: 구직자에게 어떤 명목이든 돈을 받으면 안 됨.
- 주의 3: 사용료가 "채용 공고·관리 도구 이용료"처럼 **서비스 이용료**로 보이도록 구성 (기능: 근태 관리, 공고 관리, 문서 관리 등). 정확한 판단은 고용노동부 지방고용노동관서 또는 노무사에게 확인.
- 확인 질문 (노무사·고용노동부 문의용): (1) 정액 구독 사용료가 직업소개에 해당하는가 (2) 신고가 필요한가 (3) 장애인 구직 무료 알선 시 신고 의무가 있는가.
