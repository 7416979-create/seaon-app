## 1. 이번에 잘한 것 (계속 이렇게)
- 브라우저 도구가 SQL을 차단했을 때 **우회하지 않고 멈춰서 보고**했다.
- 실제 직원 0001·0002, 대표 관리자 세션을 **한 번도 건드리지 않았다**.
- 테스트 데이터에 `TST`·`tst` 접두어를 지켰고, 테스트 관리자 세션은 `admin_logout`으로 끝냈다.
- 확인하지 못한 것은 "미확인"이라고 정직하게 적었다.
- DB가 준비되기 전에 배포하면 화면이 틀리게 보인다는 것을 알고 **배포를 미뤘다**.

## 2. 이번에 생긴 문제와 팀장이 해결한 방법

### 문제 A. `schema.sql`에서 함수 6개가 사라짐 (K3)
- **원인:** 함수 블록을 "다음 `end $$;`까지"로 잘랐다. 그런데 `_employee_json`은 `language sql` 함수라 `end $$;`가 아니라 `$$;`로 끝난다. 그래서 그 뒤의 함수 6개(`_record_json`, `_request_json`, `_leave_days`, `_balance`, `_distance_m`, `_check_loc`)까지 한꺼번에 덮어써졌다.
- **발견 방법:** 커밋 diff 크기가 예상(약 10줄)보다 훨씬 컸다(76줄). `create or replace function` 개수를 세어 보니 40개에서 35개로 줄어 있었다.
- **해결:** 직전 정상 커밋(`0d1431c0`)의 파일을 기준으로, 세 함수만 정확한 끝 표시로 잘라 교체했다. 교체 후 함수 수(40), 지워졌던 함수 6개가 있는지, 세 함수가 마이그레이션과 글자 하나까지 같은지 확인했다. 커밋 `81983046`.
- **영향:** 실서버는 마이그레이션 파일로 적용했기 때문에 영향이 없었다. 저장소의 설치용 파일만 망가져 있었다.

### 문제 B. 테스트 데이터가 지워졌는지 확인하지 못함
- **원인:** Supabase SQL 편집기가 계속 멈추거나 입력을 받지 않았다.
- **해결:** 편집기를 쓰지 않고, **API로 "없는 것을 확인"하는 방법**을 썼다.
  - 테스트 직원의 링크(`emp_enter`)를 호출 → "링크가 올바르지 않거나 만료" = 직원 행 없음
  - 테스트 관리자 링크(`admin_enter`)를 호출 → "관리자 링크가 올바르지 않습니다" = 링크 행 없음
  - 이 호출은 행이 없으면 아무것도 바꾸지 않는다. 행이 있어도 이미 사용된 링크라면 오류만 내고 바꾸지 않는다.
  - **단, 실제 직원 링크와 대표 관리자 링크로는 절대 하지 않는다.** 그 링크는 호출하는 순간 소진될 수 있다.

### 문제 C. 편집기에 엉뚱한 글자가 들어감
- **원인:** 한글 입력기(IME)가 켜진 상태에서 키보드 입력·붙여넣기를 하면 맨 앞에 `a` 같은 글자가 섞이거나, 화면에는 한글처럼 보인다.
- **해결:** 짧은 SQL은 `monaco.editor.getModels()[0].setValue(...)`로 넣고, **실행 전에 `getValue()`로 실제 내용을 읽어 확인**했다. 화면 모양을 믿지 않는다.

### 문제 D. PowerShell이 코드 문자열을 망가뜨림
- **원인:** 큰따옴표 문자열 안의 `` ` ``(백틱)과 `$`를 PowerShell이 먼저 해석해서 JSX 줄이 깨졌다.
- **해결:** 코드나 SQL을 넣을 때는 **작은따옴표 here-string(`@'...'@`)** 이나 Edit 도구를 쓴다. 넣은 뒤 tsc로 확인한다.

## 3. 앞으로의 규칙 (필수)

1. **파일을 기계적으로 바꾼 뒤에는 반드시 diff 크기를 본다.** `git diff --stat`이 예상보다 크면 커밋하지 말고 멈춘다.
2. **SQL 파일을 고친 뒤에는 함수 개수를 센다.** `Select-String -Pattern '^create or replace function'` 개수가 고치기 전과 같아야 한다(추가한 만큼만 늘어야 한다).
3. **SQL 함수의 끝은 두 종류다.** `language plpgsql`은 `end $$;`, `language sql`은 `$$;`. 블록을 자를 때 함수마다 끝 표시를 따로 정한다.
4. **편집기 화면을 믿지 말고 실제 값을 읽는다.** 실행 전에 `getValue()`, 실행 후에는 결과 칸(`[role=gridcell]`)을 읽는다.
5. **편집기 탭은 하나만 쓴다.** 새 탭을 계속 열지 않는다. 멈추면 그 탭을 닫고 하나만 새로 연다. 여러 개가 쌓이면 크롬 전체가 느려진다.
6. **편집기가 안 되면 API로 확인할 수 있는지 먼저 생각한다.** 테스트 토큰으로 "없음"을 확인하는 방법처럼, 데이터를 바꾸지 않는 확인 방법을 찾는다.
7. **순서: DB 변경 → 코드 → 배포.** DB가 준비되지 않았으면 배포하지 않는다.
8. **코드에 들어가는 문자열은 작은따옴표 here-string이나 Edit 도구로 넣는다.**
9. **커밋 전 자기 검토:** `git show --stat HEAD`로 바뀐 파일과 줄 수를 보고, 의도하지 않은 파일이 있으면 되돌린 뒤 보고한다.
